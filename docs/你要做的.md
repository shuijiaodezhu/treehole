## 一、上线前必做（三件）

### 1 · 配 Redirect URLs —— 5 分钟

**不做的后果**：找回密码的邮件链接会跳到一个空白页，用户以为你没做这个功能。

**在哪**：Supabase → Authentication → **URL Configuration**

| 字段 | 填什么 |
|---|---|
| **Site URL** | 正式域名，例如 `https://你的域名`（本地开发期可先填 `http://localhost:3000`） |
| **Redirect URLs** | 加两条：`http://localhost:3000/**` 和 `https://你的域名/**` |

**怎么验**：登录页点「忘记密码？」→ 填邮箱 → 收到邮件 → 点链接 →
应该回到 `/reset-password` 并能设新密码。

---

### 2 · 设 `NEXT_PUBLIC_SITE_URL` —— 3 分钟

**不做的后果**：分享出去的卡片地址是 `localhost`，别人点不开。

**在哪**：Vercel → 你的项目 → Settings → **Environment Variables**

```
NEXT_PUBLIC_SITE_URL = https://你的域名
```

改完**要重新部署**才生效。

**怎么验**：把任意页面链接粘到微信/QQ 里，预览卡片能显示出标题和那张信封图。

---

### 3 · 配 SMTP —— 10 分钟 + 挑服务商

**不做的后果**：Supabase 内置邮件服务**每小时只能发个位数**，超了**静默失败**——
用户等不到确认邮件，你也不知道为什么。这条最容易上线后才发现。

**在哪**：Supabase → Project Settings → Auth → **SMTP Settings**

可选服务：你自己的邮箱服务、Resend、SendGrid 等（都要填 host / port / 用户名 / 密码 / 发件人）。

**怎么验**：连续注册 3 个测试邮箱，**三个都能收到**确认邮件。

**顺带建议**：Authentication → Email Templates → Confirm signup 改成中文，
默认是英文的。

**定时**：Windows 任务计划程序 → 创建基本任务 → 每天一次 →
程序 `pwsh`，参数 `-NoProfile -File "C:\Users\Steve Tom\treehole\scripts\backup.ps1"` →

**验收标准（重要）**：`backups/` 里出现当天的 `.sql` 文件，
**并且你试过一次恢复**（哪怕恢复到另一个 Supabase 项目）。

## 五、我留给你的"诚实边界"（别忘了这些是真的）

1. **`robots.txt` 只是请求** —— 规矩的爬虫遵守，不规矩的不遵守。要"整站绝对别被抓"得加全局 `noindex`（说一声我就加）。
2. **冬日信箱的匿名是"界面层面"的** —— 数据库里仍记着这封信属于哪个信箱（否则回信送不到）。站主后台不显示、也查不到名字，但理论上打开 Supabase 查那行 uuid 还是能对出来。
3. **限流的客户端那层抓包就能绕** —— 真正拦得住的是数据库触发器（已装）。
4. **免费版 Supabase 7 天没活动会暂停** —— 访客会看到打不开的站，得你去后台唤醒。这比容量更容易先撞上。
5. **"图片公开"不等于"好友可见"** —— 现在是"链接猜不到"，不是权限隔离。
6. **没有验证过的备份不算备份** —— 见第二部分的验收标准。
7. **好友列表排序** 依据 `last_message_at`（数据库维护，已实测触发器有效），不再受消息条数限制。
