# 部署步骤（不用 GitHub，直接从本地传）

## 为什么不用 GitHub 那条路

从你这台机器测的结果：

| 目标 | 结果 |
|---|---|
| **github.com:443** | ❌ **不通**（连接被重置） |
| **vercel.com:443** | ✅ 通 |
| registry.npmjs.org:443 | ✅ 通 |

所以「推到 GitHub → Vercel 自动拉取」这条路现在走不通。
但 Vercel 官方命令行工具是**把本地文件直接上传**的，**不需要 GitHub**，
而且你那 78 个还没推上去的提交照样会被部署 —— 用这条。

**顺带提醒**：因为推不上 GitHub，你的代码目前**只在这台电脑上**。
硬盘坏了就没了。等哪天网络能连上 GitHub（换个网络或用代理），
记得 `git push` 一次。

---

## 前置条件（你这台机器都满足了）

- ✅ Node.js（`node --version` 能出版本即可）
- ✅ npm（项目用的是 npm，锁文件是 `package-lock.json`）
- ❌ 不需要 pnpm、不需要 Docker、不需要装任何东西

---

## 第一步：登录 Vercel（约 2 分钟）

在 PowerShell 里：

```powershell
cd "C:\Users\Steve Tom\treehole"
npx vercel login
```

会问你用哪种方式登录，**选 `Continue with Email`**（用邮箱）：

- ⚠️ **别选 GitHub** —— 那个流程要跳转到 github.com，你这网络过不去
- 选了邮箱后，它会让你填邮箱 → 去邮箱里点确认链接 → 回到终端就登录好了

> 这一步会顺便给你注册一个 Vercel 账号（用这个邮箱）。

---

## 第二步：第一次部署（约 5 分钟）

```powershell
npx vercel
```

第一次会让你回答几个问题，**照下面的填**：

| 它问什么 | 怎么答 |
|---|---|
| Set up and deploy …? | **Y**（回车） |
| Which scope …? | 回车（选默认的那个） |
| Link to existing project? | **N**（回车） |
| What's your project's name? | 直接回车（默认 `treehole`） |
| In which directory is your code located? | 直接回车（`./`） |
| Want to modify these settings? | **N**（回车） |

然后就等它构建。**成功的话最后会打印一个地址**，形如：

```
✅  Production: https://treehole-xxxx.vercel.app
```

**这个地址就是你的域名，抄下来。**

（第一次那条是预览部署，域名会带一串随机后缀；下一步 `--prod` 之后
会有个更干净的正式地址。）

---

## 第三步：发布到正式环境（约 2 分钟）

```powershell
npx vercel --prod
```

完成后它会打印 **Production 地址**，形如 `https://treehole-xxxx.vercel.app` ——
**这才是你要发给朋友的地址**，也是后面所有配置里要填的域名。

---

## 第四步：填环境变量并重新发布（约 3 分钟）

把域名填进去，分享卡片、robots、sitemap 才会用对地址。

```powershell
npx vercel env add NEXT_PUBLIC_SITE_URL production
# 它提示 Input value 时，粘贴：https://treehole-xxxx.vercel.app  （换成你的）
# 然后回车

npx vercel --prod      # 重新发布，让变量生效
```

---

## 第五步：Supabase 里配两处（约 5 分钟，**这步不做朋友注册会卡住**）

Supabase → Authentication → **URL Configuration**

| 字段 | 填 |
|---|---|
| **Site URL** | `https://treehole-xxxx.vercel.app` |
| **Redirect URLs** | 加两条：`http://localhost:3000/**` 和 `https://treehole-xxxx.vercel.app/**` |

> 为什么必须：你开着 `Confirm email`，朋友注册后那封确认邮件里的链接
> **默认跳到 Site URL**。它还写着 localhost 的话，朋友点了会跳到自己电脑上打不开。

---

## 第六步：验一遍（约 5 分钟）

1. 用**手机流量**（不是家里 WiFi）打开那个地址 —— 顺便看国内可达性
2. 用**新邮箱**注册 → 收到确认邮件 → 点链接 → 登录
3. 登录后：写一条朋友圈、发一张图、进小屋发条消息
4. 拿另一个账号互发一句，确认**实时**能到

任何一步不对，把现象告诉我。

---

## 以后怎么更新

改完代码后，两条命令：

```powershell
npx vercel --prod
```

**不用 build、不用 push**（Vercel 那边会自己装依赖、自己 build）。

---

## 常见问题

**Q：`npx vercel` 卡住不动？**
大概率在下载 CLI。等一下；还是不动就 `npm config get registry` 看看是不是被指到了慢源。

**Q：部署失败，报 build 错误？**
把终端最后 30 行发我。本地 `next build` 是能过的，所以多半是环境差异（Node 版本、依赖装法），照着报错能定位。

**Q：想以后接 GitHub 自动部署？**
可以，但要先能连上 github.com。等你能 push 了，在 Vercel 项目里
Settings → Git → Connect Git Repository 接上即可。

**Q：以后买域名了怎么换？**
三步：Vercel 项目 → Settings → Domains 里加自定义域名 →
Supabase 的 Site URL 与 Redirect URLs 各改/加一条 →
`npx vercel env add NEXT_PUBLIC_SITE_URL production` 换成新域名再 `--prod`。
**代码一行不用改。**
