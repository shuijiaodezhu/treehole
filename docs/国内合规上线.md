> 分三个阶段：**备案 → 上线 → 数据库回国**。第一阶段只花 ¥130 左右，主要成本是**等**。

## 0. 先看清三件事（决定了后面所有选择）

### ① 个人备案**不能**做交互式内容 ⚠️ 最关键

| | |
|---|---|
| 个人备案（用身份证）| 只能做「**个人博客 / 个人展示 / 学习记录**」类网站 ✗ |
| | **论坛、社区、评论区、私信、用户发帖** —— 这类**交互式服务**，个人备案基本**通不过** ✗ |
| 企业备案（用营业执照）| 可以 ✗ 但要有营业执照 ✓（个体户执照也算 ✓）|

**我们这个站是什么**：发帖、评论、私信、朋友圈、匿名信箱 —— **全是交互式** ✓
→ 所以要么办**个体工商户/公司** 走企业备案 ✓
→ 要么备案时**如实降级**为「个人记录/展示」，但之后加了用户互动 = **与备案信息不符** ✗（这是会被注销备案的场景 ✗）

> **结论**：如果想认真长期做，最稳的是办个**个体工商户**（成本低、流程快 ✓ 很多地方线上就能办 ✓），
> 然后用**企业备案** ✓。个人备案这条路上，这个站的形态是走不通的 ✗。

### ② 备案期间，域名**不能**解析到境外 ⚠️

```
审核时会核查解析记录 ✗
→ 域名**不能**指向 Vercel / 香港 ✗ 否则直接驳回 ✓
→ 也就是说：**同一个域名不能一边备案一边用香港救急** ✗
```

### ③ 网站名称有雷区 ⚠️

```
✗ 不能含：论坛 / 社区 / 博客（个人）/ 新闻 / 直播 / 教育 / 医疗 / 支付
✗ 不能是纯英文（部分地区要求中文名）
✗ 不能含"中国 / 国家 / 中华"等字样
✓ 可以：你的来信 / 来信 / 树洞笔记 —— 但"树洞"在某些省份会被要求说明用途
→ 名称**建议按"个人作品 / 个人记录"来写** ✓ 简单、好过 ✓
```

## 2. 第二阶段：上线（备案通过后，半天）

### 2.1 服务器准备（Ubuntu 22.04）

```bash
# 以 root 登录后：
apt update && apt upgrade -y
apt install -y nginx certbot python3-certbot-nginx git curl

# 防火墙：只开 22 / 80 / 443
ufw allow 22 && ufw allow 80 && ufw allow 443 && ufw enable

# 建一个部署用户（别一直用 root）
adduser deploy && usermod -aG sudo deploy
```

### 2.2 两条路线，先走 A

**A. 反向代理到 Vercel（当天可用，最简单）**

```nginx
# /etc/nginx/sites-available/dear
server {
    listen 80;
    server_name 你的域名.cn;

    location / {
        proxy_pass https://treehole-rho.vercel.app;
        proxy_set_header Host treehole-rho.vercel.app;      # 关键：让 Vercel 认这个 Host
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_ssl_server_name on;
        proxy_redirect off;
    }
}
```

```bash
ln -s /etc/nginx/sites-available/dear /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx

# HTTPS（免费证书，自动续期）
certbot --nginx -d 你的域名.cn -d www.你的域名.cn
```

> 这一步解决「**能不能开 + 合不合规**」✓
> ✗ 但**不解决"快"**：内容还是从境外取 ✓（每次都要跨境一趟 ✓）

**B. 整站搬到大陆服务器（第二阶段做完再做）**

· 构建要内存：2核2G 需要加 2G swap（否则 next build 容易 OOM ✗）
· 逐条命令我可以单独写一份（等你要做时再说 ✓）

### 2.3 必须改的代码/配置（三处，漏一处就出问题）

## 3. 第三阶段：数据库回国（真正变快的一步）

**为什么必须做**：服务器在国内 ✓ 但数据库（Supabase）在境外 ✗
→ 每次查询跨境 100-300ms ✗ 页面一多就明显卡 ✓

### 3.1 要换掉的东西

| 现在 | 换成 | 难度 |
|---|---|---|
| Supabase Postgres | **同一台服务器上的 Postgres**（或国内云数据库 ✓）| 中 ✓ |
| supabase-js 的 `.from().select()` | 自己的 API 路由 / 或 PostgREST 自建 | **大** ✗ |
| Supabase Auth（登录）| 先用着 ✗（登录跨境一次可以忍 ✓）| 可延后 ✓ |
| Supabase Storage（图片）| 大陆 OSS / 或服务器本地 | 中 ✓ |
| Supabase Realtime | 轮询 / SSE | 中 ✓ |

### 3.2 表结构从哪来

```
仓库里 supabase-*.sql 就是全部表结构 ✓（含 RLS、触发器、函数 ✓）
→ 在大陆的 Postgres 上按顺序跑一遍即可 ✓
→ 数据迁移：Supabase 后台能导出 SQL/csv ✓ 再导入 ✓
```

### 3.3 代码改造的边界（重要）

```
代码里跟 Supabase 打交道的地方集中在：
  app/lib/supabase.ts        ← 客户端入口
  components/*.tsx 里的 .from(...) 调用
→ 建议：**写一个薄封装**（同样提供 .from().select().eq() 的链式接口 ✓）
  指向自己的后端 ✓ 这样上层调用点几乎不用改 ✓
→ 一次做透很难 ✗ 分模块做 ✓（先做「读多写少」的页面 ✓）
```
