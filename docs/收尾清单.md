## 阶段一：上线阻断项（这些没做，站点就是半成品）

### 1. 🔴 跑 SQL

**为什么**：冬日信箱、登录设备、注销申请、限流兜底全依赖它。现在前端已经写好了，
但表不存在，点开只会看到「还没开通」。

**怎么做**：Supabase → SQL Editor → 依次跑

2. `supabase-winter-mailbox.sql`（冬日信箱）
3. 其余按 README 的表格对照自己的需要

**算做完**：跑 `select tablename, rowsecurity from pg_tables where schemaname='public';`
能看到 `winter_letters`、`login_logs`、`deletion_requests` 且 `rowsecurity = true`。

### 2. 🔴 配 Redirect URLs

**为什么**：找回密码的邮件链接会跳到 `Site URL`。没配的话链接跳空——
用户点了没反应，还以为你没做这个功能。

**怎么做**：Supabase → Authentication → URL Configuration

- Site URL：正式域名（本地开发期可先填 `http://localhost:3000`）
- Redirect URLs：加 `http://localhost:3000/**` 和 `https://你的域名/**`

**算做完**：走一遍「忘记密码 → 收邮件 → 点链接 → 设新密码 → 登录成功」。

---

### 3. 🔴 配自定义 SMTP（或者先接受"只能自己测"）

**为什么**：Supabase 内置邮件服务每小时只能发**个位数**封，超了静默失败——
用户等不到确认邮件，你也不知道为什么。这是最容易被忽略、又最影响真实用户的一条。

**怎么做**：Project Settings → Auth → SMTP Settings，填一家 SMTP
（自有邮箱服务 / Resend / SendGrid 都行）。

**算做完**：连续注册 3 个测试邮箱，都能收到确认邮件。

> 只是自己用、不开放注册 → 这条可以先跳过，但要**知道**限制在哪。

---

### 4. 🔴 设 `NEXT_PUBLIC_SITE_URL`

**为什么**：分享卡片（OG）的地址来自它。不设就是 localhost，
分享到微信/QQ 里别人点不开。

**怎么做**：Vercel → Settings → Environment Variables →
`NEXT_PUBLIC_SITE_URL=https://你的域名`，然后重新部署。

**算做完**：把一个页面链接粘到微信里，预览卡片能显示出标题和那张信封图。

## 阶段二：上线后第一周（体验上的真问题）

### 5. ✅ 聊天不实时——对方回你，你看不到（已做）

**已完成**：抽出 `components/chat-realtime.ts`，两个聊天界面共用。

- 订阅 `postgres_changes`，filter 到当前会话
- **外加每 20 秒的兜底轮询**——因为 Realtime 需要在 Supabase 里把 `messages`
  加进发布（见 `supabase-realtime.sql`），那个开关我验证不了，
  所以不把功能全押在它上面；切到后台就不拉，省流量
- 两条路走同一个去重逻辑，不会冒出重复气泡
- 正开着会话时收到消息，会顺手标记已读，角标不会又冒出来

**顺带发现一件值得记的事**：把订阅逻辑直接写在组件里，会让
**React 编译器跳过整个组件的优化**（表现是文件里两条旧的 eslint 豁免突然变成
unused）。抽成自定义 hook 之后恢复正常。以后再加订阅类逻辑就照这个来。

**你要做的**：跑一次 `supabase-realtime.sql`（不跑也能用，只是慢 20 秒）。

**算做完**：两个浏览器分别登录两个账号，一边发，另一边**不刷新**就能看到。

### 7. 🟠 RLS 全面体检（**已跑，结论如下**）

用 `supabase-rls-audit.sql`（只读）跑完了 29 张表：

- **🔴 0 个** —— 没有任何表是「RLS 没开」。这是最要紧的一条，可以确定：
  脚本的排序把 🔴 放最前，而第一行是 🟠，所以一个 🔴 都没有。
- **🟠 2 个 → 已修** —— `user_files`（储物箱）与 `user_plans`（计划书）：
  表在、RLS 开着、**一条策略都没有** → 前端读写**全部被拒**，也就是这两个功能
  是坏的（不是不安全，是不可用）。原因：这两份 SQL 里建表在上、策略在下，
  当时跑的应该是较早的版本（或执行中断）。
  **已重跑 `supabase-vault.sql` 与 `supabase-plans.sql` 并确认**：
  前者返回 6 条策略（storage 3 + user_files 3），后者返回 4 条（select/insert/update/delete）。
- **其余 27 张表**：策略数 ≥ 1，正常。

**还剩一件事**：`media` 桶的读策略是给 `{public}` 的（含未登录），
需要决定是否收紧。已确认上传路径含 6 位随机字符（`${uid}/${Date.now()}-${随机6位}`），
所以 URL 猜不到——这属于「不公开列出」，而不是「谁都能翻到」。
